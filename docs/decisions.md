# Decision log

The normative specification is [`spec/`](spec/README.md), extracted from the frozen record
[`../rfcs/0001-funky-secure-v1/rfc.md`](../rfcs/0001-funky-secure-v1/rfc.md). This page is the review
surface for the decisions behind it: first the product decisions of that record's Appendix A,
then the implementation decisions taken during F0–F4 and recorded in
[`../odd/tasks/funky-secure-v0.1.md`](../odd/tasks/funky-secure-v0.1.md), and after those the ones
its successor records added — [`../rfcs/0002-human-output-v2/rfc.md`](../rfcs/0002-human-output-v2/rfc.md)
for I-25 to I-28 and
[`../rfcs/0003-first-ten-minutes/rfc.md`](../rfcs/0003-first-ten-minutes/rfc.md) for I-29 to I-32.

Nothing here restates the RFC. Each line names the decision and the section or file it binds.

## Product decisions (RFC Appendix A)

| # | Decision | Binds |
|---|---|---|
| D-1 | The product both analyses a project and initializes it with good practices. | 1.1 |
| D-2 | pnpm's own defaults are the baseline; the tool does not re-implement them. | 1.3, 4.1 |
| D-3 | pnpm is recommended and npm is migrated, never required. | G4, R3, 11.3 |
| D-4 | The product must be lighter and better focused than the one it replaces. | 4, 8.4 |
| D-5 | A global scan that overwrites no user configuration, plus project and workspace scanning. | 7, 12 |
| D-6 | No floating ranges and no automatic dependency merges. | R5, R9 |
| D-7 | In CI: Actions pinned by SHA, sensitive files and `.env` covered by ignore rules. | R6, R7, R8 |
| D-8 | Own repository and package named `funky-secure`, no version suffix. | 6 |
| D-9 | Nine rules now, the rest in v2. | 8.2, 8.3, 8.4 |
| D-10 | `funky-ai` is out of scope and untouched. | 17 |
| D-11 | `exact-versions` is `warn` in `baseline` and `error` in `strict`. | R5, 9.1 |
| D-12 | `init` does not write `pnpm-workspace.yaml` in v0.1 except the managed block, and only with `--apply`. | 11.2 |
| D-13 | Receipt-driven development is enabled for this workspace. | session control |
| D-14 | Help is always current, and complete architecture documentation is a deliverable. | 13, 14 |
| D-15 | The RFC session ends with the document; implementation happens in another session. | whole document |
| D-16 | R4 measures the gate, not the number: a preset-dependent floor, `warn` in `baseline`, `error` in `strict`. | 8.2 R4, 9.1, 9.4, 11.2 |

## Implementation decisions (F0–F4, and after)

| # | Decision | Binds |
|---|---|---|
| I-1 | The ignore probe is split in two lists: `IGNORE_CANDIDATES` is what R7 requires to be ignored, `PROBED_IGNORE_PATHS` adds `pnpm-lock.yaml` so R2 can report an ignored lockfile. One probe, per-path verdicts; merging them would have made R7 demand an ignored lockfile. | `src/lib/targets.js`, 8.2 R2/R7 |
| I-2 | `--scope repo` still resolves the answering pnpm version, but not its configuration (`machineFacts(collector, { withConfig: false })`); `ctx.machine.configOutOfScope` tells `quarantine` that the absent configuration is excluded by contract, not an unavailable probe. | `src/lib/scan.js`, `src/lib/targets.js`, `src/rules/quarantine.js`, 7.2 |
| I-3 | Passing findings are never rendered as findings: the human renderer rolls them up into one `passing …` line and the JSON renderer drops them, because the report already counted them. | `src/lib/render-human.js`, `src/lib/render-json.js`, 10.1, 10.3 |
| I-4 | `quarantine` reports on `repo-root` with `scope: ['repo']`, not on the machine section: the effective value is a repository posture even though the fact comes from the manager. | `src/rules/quarantine.js`, 7.1, Appendix D.1 |
| I-5 | R6 filters the complete tracked list by basename instead of adding a `:(glob)` pathspec probe; the equivalence holds because the tracked list is complete, and the mandatory template exclusion list is what prevents the `.env*` over-match. | `src/rules/env-not-tracked.js`, 8.2 R6, E4 |
| I-6 | R9 rides its configuration signal on a `pass` finding instead of a failure: `info` is a severity in the report contract, not a status, and v0.1 has no per-finding severity override. | `src/rules/no-bot-auto-merge.js`, 8.2 R9 |
| I-7 | R5 classifies specifiers without resolving any: `workspace:*`, `workspace:1.2.3` and `link:` are exact; `workspace:^`, `file:`, partial versions, wildcards, tags and URL/git specifiers are floating; an unrecognized shape is not reported. | `src/rules/exact-versions.js`, 8.2 R5 |
| I-8 | W4 never replaces a config document: a file that already declares exactly `{ "preset": "strict" }` is `would-skip` and keeps its own bytes; any other preset, any other key, an unparseable file, an unreadable file, or a config discovered outside the repository root is a `conflict` with the reason named. | `src/lib/writers.js` (`writeStrictConfig`, `planStrictConfig`), `src/commands/init.js`, 11.2 |
| I-9 | A tracked root `.npmrc` without `_authToken=` is exempt from the ignore requirement in both readers — the rule does not demand it be ignored and the `.gitignore` block does not add it — because a tokenless `.npmrc` is configuration a repository may deliberately commit. | `src/lib/targets.js` (`npmrc.tokenlessTracked`), `src/rules/sensitive-ignored.js`, `src/lib/writers.js` (`trackedNpmrcFacts`), 8.2 R7 |
| I-10 | With `--format json`, `init` writes the plan document to stdout and nothing else; the `write` ledger of `--apply` goes to stderr, because a second document on stdout would make the plan unparseable. | `src/commands/init.js`, 10.5, 11.2 |
| I-11 | The release guard runs npm through its CLI entry point (`node .../npm-cli.js`) rather than a `npm.cmd` shim: a `.cmd` is not executable without `shell: true` on Windows (E7), and the shell fallback earns the DEP0190 warning. It reads `files` from `package.json` instead of duplicating the contract, so the check cannot drift from what npm packs. | `scripts/release-guard.js`, `tests/release-workflow.test.js`, 17.3, 17.4 |
| I-12 | Publication is reachable only from a `v*` tag, and the guard treats a missing tag as a local dry run instead of a failure: `npm publish` from a workstation stays possible for a maintainer, but CI always passes `--tag "$GITHUB_REF_NAME"`, so a mismatch there is fatal and publishes nothing. | `.github/workflows/release.yml`, `package.json` (`prepublishOnly`), 17.3 |
| I-13 | `ci-no-safety-overrides` is `warn` in `baseline` and `error` in `strict`, because friction 1 needs no deviation from 4.2/9.1: removing a flag is one edit, and the finding names an explicit override of pnpm's own CI default rather than a preference, so a repository that never overrides the default is never touched. The two codes keep the frozen lockfile and the lifecycle scripts apart, because the delivery contract (17) rests on the lockfile and the install scripts are the code-execution path. | `src/rules/ci-no-safety-overrides.js`, `docs/rules/ci-no-safety-overrides.md`, 8.3 (0.2 scope), 16 F5 G2, 9.1 |
| I-14 | `pull-request-target` is `error` in `baseline` and `error` in `strict`, a declared deviation from 9.1 (friction 1 starts at `warn` in `baseline`): the finding fires only on the combination of the trigger and a head checkout, removing either half is one edit, and no repository that never writes `pull_request_target` is touched — so the friction class of the finding is not the friction of the fix, as with R8. The trigger is read by `declaresTrigger` in the shared workflow reader, which R9 now uses too, instead of the second trigger parser it grew in v0.1. | `src/lib/workflows.js` (`declaresTrigger`), `src/rules/no-bot-auto-merge.js`, `src/rules/pull-request-target.js`, `docs/rules/pull-request-target.md`, 8.3 (0.2 scope), 16 F5 G3, 9.1 |
| I-15 | `workflow-permissions` keeps the 9.1 severity for friction 1 — `warn` in `baseline`, `error` in `strict` — and does not take the `error`/`error` deviation of I-13/I-14, because its weakest finding is about a fact the tool cannot read: GitHub's default for `GITHUB_TOKEN` is a repository setting, not a file, so a job that inherits the repository setting without any declaration is not knowable as a deviation offline and `baseline` cannot call it an error; `strict` can, because there the declaration is required. The rule reads the declaration, never a line scan: the shared reader carries the workflow-level and per-job `permissions:` as a form (`write-all`, `read-all`, `none` for `{}`, or `map` with the entries) plus the 1-based line, and refuses a `permissions:` value it cannot attribute, naming the line. A job-level `write-all` is reported at the line of that job's `permissions:` key, since that key is what the fix replaces, and the finding carries the job id so the reader still knows which job it is. | `src/lib/workflows.js` (`parseWorkflow`), `src/rules/workflow-permissions.js`, `docs/rules/workflow-permissions.md`, 8.3 (0.2 scope), 16 F5 G4, 9.1 |
| I-16 | CI runs the suite on Ubuntu and Windows, at the declared `engines.node` floor and at Node 22, and `.gitattributes` forces `eol=lf` on every checkout. The product branches on the platform (the `%~dp0` shim expansion, the `.cmd` spawn rules, the release guard's npm invocation), so a Linux-only gate leaves those paths unverified; and the golden gate compares bytes, so a CRLF checkout would fail it for a reason that is not the code and would invite regenerating the goldens with the wrong endings. Four legs, free on a public repository. | `.github/workflows/ci.yml`, `.gitattributes`, `tests/ci-coverage.test.js`, 15.4 |
| I-17 | `engines.node` is `>= 22` and the matrix runs `22` and `24`: the previous floor was an end-of-life runtime that the matrix executed as if it were supported, which proves a promise about a runtime without security fixes. Actions are pinned to the releases that were current when this shipped (`checkout v7.0.1`, `setup-node v7.1.0`, `pnpm/action-setup v6.1.0`) with the bump procedure in the workflow header, `check-latest: true` floats the runtime patch, and the `pnpm install` step is gone while `pnpm/action-setup` stays: with zero dependencies nothing is resolved, but the self-scan needs an answering pnpm or `package-manager-pin` degrades to a silent skip. | `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `.gitattributes`, `package.json`, `tests/ci-coverage.test.js`, 15.4, 16 F5 |
| I-18 | The report's `provenance` is resolved once in `scan` — preset source, whether this repository's own `pnpm-workspace.yaml` declares the quarantine key, and whether the machine scope was excluded — and both renderings read the same object. It never attributes an effective pnpm value to the project or the machine, because E2 measured that the effective configuration reports no origin; the human line and the JSON field therefore say "declared in …" or "not declared in this repository" and nothing stronger. | `src/lib/scan.js` (`provenanceOf`), `src/lib/report.js`, `src/lib/render-human.js`, `src/lib/render-json.js`, 9.4, 10.2, 10.3 |
| I-19 | An exit-2 message is two lines: `funky-secure: <action>` and `reason: <diagnosis>`. The action is carried on the error by the site that knows it (a usage error names the accepted values, a refusal names the branch to switch to) and falls back to a class default, so `src/lib/config.js` and `src/lib/policy.js` need no change and still produce an actionable first line. | `src/cli.js` (`exitMessage`, `usage`), `src/commands/explain.js`, `src/commands/migrate.js`, `src/lib/plan.js`, 4.6, 10.4 |
| I-20 | Every finding whose status is `fail` carries an action; `{ kind: 'none' }` is reserved for `pass` and `skip`, and a test walks the golden fixtures asserting that every rendered `✖`/`⚠`/`ℹ` line is followed by a `→`, plus a non-vacuity assertion that the walk reaches the two rules that used to be empty. Where no shell command is honest — deleting a workflow step — the remediation is `manual` and names the file and the 1-based step line the finding already reports. `exact-versions` prints `pnpm pkg set '<section>.<name>=<version>' && pnpm install` because `pnpm add --save-exact <name>@<range>` was measured to exit 0 and change nothing on pnpm 12.3.4. | `src/rules/*`, `tests/cli.test.js`, `docs/rules/exact-versions.md`, 4.6, 8.2 R2/R5/R6/R9 |
| I-21 | A skip caused by the scope contract is a message the rule owns, naming what was not verified and the command that verifies it; `quarantine` treats `ctx.machine === null` as the same contract (`machine-out-of-scope`) while keeping `no-pnpm-config` for an available machine that answers without configuration, so the existing probe-unavailable test still describes a real case. | `src/rules/package-manager-pin.js`, `src/rules/quarantine.js`, 7.2, 10.3 |
| I-22 | The repository has two axes, and each document belongs to exactly one (S1-S3). A **record** is immutable once `implemented` or `closed`: `rfcs/NNNN-<slug>/rfc.md` and `odd/tasks/<feature>.md`, whose Log is append-only. The **present** is edited freely and has one owner: `docs/spec/` for the contract and this page for the decisions. The record of 2026-10-28 is frozen at revision 7 under `implemented`; correcting it is a dated `## Errata` append or the next numbered record, never a rewrite. | `rfcs/README.md`, `odd/tasks/rfc-registry.md`, `CONTRIBUTING.md` |
| I-23 | The contract was **copied**, not cut, out of the frozen record: `docs/spec/{identity,scope,rules,policy,report,commands,machine,documentation,layout}.md` and `docs/delivery.md` are verbatim slices of sections 6-14 and 17, so the record keeps its prose and the spec becomes the authority for the present. The duplication that this creates with `docs/rules/<id>.md` is resolved by role instead of by deletion: the spec states the obligation, the page explains it and names the spec as normative. | `docs/spec/`, `docs/delivery.md`, `tests/drift.test.js` |
| I-24 | The drift gate enforces the split rather than trusting it: the record must still carry sections 1-21 in order (history is not edited silently), `docs/spec/README.md` must map every one of them to a file, and every mapped file must still contain its section verbatim. A section number stays the citation across the repository, so `10.3` and `11.2.1` keep resolving after the move. | `tests/drift.test.js`, `docs/spec/README.md` |
| I-25 | The catalog gains a `label` — a short noun phrase naming the subject of a finding (`Lockfile`, `Sensitive files`) — beside `title`, which stays the sentence `--help` and `explain` print. A heading needs the subject of the finding, and a title is a claim about the repository: `ci-no-safety-overrides` carries a 67-column one, so reusing it would put a sentence where a name belongs and lengthen every heading past the width bound. The catalog remains the single source of names, and the drift test asserts one label per rule, unique, at most 28 columns and emoji-free, so the id fallback in the renderer is a safety net and never a state the catalog may be in. | `src/rules/*`, `tests/drift.test.js`, 8.2, 10.3, 13.1 |
| I-26 | `summary` and `verdict` move from the bottom of the human report to the header, immediately after the provenance line, keeping their names and their nine-character gutter, and the `next` block keeps the same gutter at the end. The counts are what a reader asks for first, and the two labels are what an existing grep or script already matches, so the move reorders the report without costing a consumer the lines it looks for. A separator of 90 `─` marks where the evidence starts, narrow enough not to compete with the text above it. | `src/lib/render-human.js`, `src/lib/report.js`, 10.3 |
| I-27 | Skips collapse by target: two or more skipped rules print one `–` line naming their labels and the command that expands them, while a target with exactly one keeps that rule's own block with its reason and verifying command. One block per skip drowned the findings in prose, and a reason hidden behind a flag is a reason the reader will not find; a single reason costs three lines, so no flag is needed for it. `--verbose` is the escape hatch the collapsed line names, and it restores every rule id, the per-rule skip reason, the passing rule ids and the machine block's paths without changing one byte of the JSON document. | `src/lib/render-human.js`, `src/cli.js`, 10.3, 11.1 |
| I-28 | No rendered line exceeds 96 columns: messages and actions wrap, never truncate, and the only value shortened is a machine path — the store and the executable of the `MACHINE` block — cut in the middle with `…`. Those paths are the only value whose length is not the tool's to bound, since the machine supplies it, and every other long value is text the report owns; a middle cut keeps both ends that identify a path and a fixed cut point keeps the rendering deterministic. Truncating a message would meet the same bound by deleting the fact instead of moving it to the next line. | `src/lib/render-human.js`, 10.3, 12.1 |
| I-29 | The `starter` preset runs exactly six rules at the severity they already carry in `baseline` — `package-manager-pin`, `lockfile-committed`, `foreign-lockfile`, `quarantine`, `exact-versions`, `sensitive-ignored` — and turns the other six `off` through one map, `PRESET_SEVERITY`, beside `PRESETS` instead of a second catalog. The foreign lockfile is in the set because a framework-generated project — a `create next-app` repository with `package-lock.json` and no `pnpm-lock.yaml` — is precisely the repository the preset exists for, and the rule that says a second package manager still shapes it was the one a beginner never saw; it keeps the `warn` of `baseline`, so nothing gets louder. `env-not-tracked` is deliberately left off: it reports an environment file that is already tracked, which cannot exist in a repository minutes old and is a day-two repair, while the day-zero half of the same question is `sensitive-ignored`; both are visible in the same `not run` line, so leaving one off hides nothing. An added catalog rule is `off` under `starter` until the map says otherwise, because a preset that claims to check less must fail in the safe direction, and `quarantineFloor('starter')` is the manager default, never the `4320` of `strict`. | `src/lib/policy.js` (`PRESETS`, `PRESET_SEVERITY`, `quarantineFloor`), 9.1, 9.4, 0003 L10 |
| I-30 | The `not run` line is restricted to rules the **policy** disables, and `--only` / `--ignore` never produce it. `offByPolicy` reads `policy.severities`, which is the preset plus the config `rules` map; `--only` and `--ignore` only remove rules from `policy.active`, so narrowing one run stays what it is — a choice about this run, not a claim that the repository is checked less. A line that fired for a flag would turn a per-run narrowing into a statement about the policy and would make the report's coverage depend on how the reader invoked it. | `src/lib/render-human.js` (`offByPolicy`, `notRunLines`), `src/commands/scan.js`, 9.2, 10.3, 11.1 |
| I-31 | `start` does not write, even though the request behind it ("que lo configure") invited it. Every writer is a security surface — `validateWriteTarget`, the digest of the exact bytes, the dirty-tree refusal — and a second one doubles the review load without adding a capability, so `start` names `funky-secure init --apply` and lets the one writer write. It reads the same collection and the same plan `init` derives rather than computing its own view, because a second engine could contradict the report about the same repository. It exits `0` in every state, including a repository already past the start: guidance that can fail is a gate, and the gate is `scan`. | `src/commands/start.js`, 11.7 |
| I-32 | The `not run` line is human output only. The JSON document of 10.2 is frozen in record 0003 and gains no coverage field: a machine reader already has `policy.preset` and the counts that preset produced, and a field would be new contract surface with its own consumers, decided in a record that does not otherwise touch the JSON. The line also gets its own width, 86 columns, four short of the report's 96, because it is a set of labels to scan against the catalog rather than prose, and it is produced by one helper for both the report and `start`, so the two cannot disagree about what the recommended preset leaves unrun. | `src/lib/render-human.js` (`notRunLines`, `HONESTY_WIDTH`), `src/commands/start.js`, 10.2, 10.3 |
| I-33 | The package ships an agent skill, and the skill may name commands but no flags, no rule ids and no message text (0004). A drift gate reads every `funky-secure <word>` occurrence and fails when the word is not a command the CLI dispatches, so the skill cannot rot silently the way a second copy of the surface would; `--help` and `explain` stay the only complete reference, and the documentation set of 13.4 does not grow. | `skills/funky-secure/SKILL.md`, `skills/README.md`, `package.json` (`files`), `tests/drift.test.js`, 13.4 |
| I-34 | Distribution is a package install, not a copy: an npm package with `skills/` and the `pi` manifest is a Pi package, so `pi install npm:funky-secure` loads the skill and `pi update` keeps it in step. The `pi-package` keyword adds it to the gallery. The copy route stays documented only as the fallback for runtimes with no package mechanism, where the tarball makes `node_modules/funky-secure/skills/` the canonical source. | `package.json` (`pi`, `keywords`), `skills/README.md`, `rfcs/0004-agent-skill/rfc.md` |
