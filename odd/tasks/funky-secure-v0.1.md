# funky-secure v0.1 — supply-chain auditor and initializer

Specification: `rfcs/funky-secure-rfc.md`, revision 2 (v1.1). The RFC is normative; this document
tracks execution and records only decisions and evidence taken during implementation.
Branch: `main` until the first product commit, then `feat/v0.1`.

## Specs

S1 — The product is `funky-secure`: own repository, npm package and binary with the same name, no
version suffix anywhere, release line starting at `0.1.0`, MIT, Node `>= 20.11`, zero runtime and
zero development dependencies (RFC 4.7, 6.2, 14, 15).

S2 — v0.1 ships exactly nine stateless rules and no writes outside `init --apply`:
`package-manager-pin`, `lockfile-committed`, `foreign-lockfile`, `quarantine`, `exact-versions`,
`env-not-tracked`, `sensitive-ignored`, `actions-pinned-sha`, `no-bot-auto-merge`. Declared
severities per preset are normative, including the three declared deviations (RFC 8.2, 8.4, 9.1).

S3 — `scan` is read-only, deterministic (same repository state → byte-identical output) and speaks
the report contract of RFC 10: `Finding` with `code`, only `fail`/`skip`/`error` serialized,
`summary` counting each verdict once, exit `0`/`1`/`2` (RFC 10.1-10.5, 4.9).

S4 — `init` prints a plan by default and, with `--apply`, performs exactly W1a, W1b, W2, W3 and W4:
the quarantine gate flip (`minimumReleaseAgeStrict: true`), the `strict`-only floor
(`minimumReleaseAge: 4320`) in the same managed block of `pnpm-workspace.yaml`, the managed block in
`.gitignore`, `packageManager` in `package.json`, and `funky-secure.config.json` only for
`--preset strict`. It refuses a dirty target file, is idempotent by marker, and never writes the
manager-owned keys (RFC 11.2, 4.3, OD-1).

S5 — `migrate` prints the five-step plan and `--apply` performs step 4 only, with its three refusals
(no `pnpm-lock.yaml`, dirty tree, default branch) (RFC 11.3, 11.5).

S6 — Help, `explain` and `docs/rules/<id>.md` are renderings of the catalog, gated by
`tests/drift.test.js`; `docs/architecture.md` lists only modules that exist (RFC 13).

S7 — The repository dogfoods the product: CI runs the suite, the drift gate and
`scan --scope repo --fail-on warn`, and a test asserts the self-scan is clean (RFC 15.4, 20.10).

S8 — E1-E8 are blocking before the rule that depends on them ships, and an outcome that contradicts
the RFC amends the RFC in the same work unit (RFC 15.5, 19.13-19.18).

S9 — Test-first where the expected outcome can be written before the code: the nine rules, the pure
lib modules and the command contracts. Not applied to collectors/probes (verified by E1-E8 plus an
injectable collector) nor to F0 scaffolding. Goldens are generated by `scripts/gen-golden.js` and
reviewed as diffs (RFC 15.1-15.3; owner asked whether TDD applied here, parent recommended the
scoped form and no objection was raised).
